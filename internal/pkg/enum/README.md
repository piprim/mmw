# mmw db enum

Turns the rows of lookup tables into [go-enum](https://github.com/abice/go-enum)
source files: one Go package per table, one enum value per row.

It only reads the database.

### Run

```shell
mmw db enum -c "postgres://user:password@localhost:5432/db?sslmode=disable" --config enums.toml
```

### Config file

```toml
# directory the packages are written in, relative to the working directory
output = "internal/domain/ref"

[[enum]]
table = "public.evenement_type" # schema defaults to public
id    = "id"                    # integer column (int2, int4, int8): the value
label = "sid"                   # column the names are derived from
comment = "label"               # optional: column written as a comment
```

`output`, `table`, `id` and `label` are required. An unknown key is an error.

With `comment`, the text of that column follows each value
(`// ddv_ID=5, // RDV de visite`) and ends up in the doc comment of the
constant:

```go
// DdvID is a EvenementType of type "RDV de visite".
DdvID
```

go-enum alone can only append the text under its own sentence, so the generated
file gets a second directive, `//go:generate go tool mmw db enum-doc
<package>_enum.go`, which rewrites the comments after go-enum has run. The
module must therefore have mmw as a Go tool.

Line breaks in the text become spaces; a NULL or empty text adds nothing.

### Output

`<output>/<package>/<package>.go`, where the package is the table name in
lowercase without underscores (the schema is ignored). The table name must
give a valid Go package name, and is matched exactly as stored in the database
(case-sensitive):

```go
// Code generated by mmw db enum. DO NOT EDIT.

//go:generate go tool go-enum --values --noprefix
package evenementtype

// EvenementType is a row of public.evenement_type.
// ENUM(
// rdv_d_estimation_ID=1,
// conge_ID=6,
// relance_r1_ID=28,
// )
type EvenementType int

// UnmarshalJSON reads the id and rejects one that is not a row of the table.
func (x *EvenementType) UnmarshalJSON(data []byte) error { … }
```

In JSON the enum is its id (`{"type":5}`). Decoding an id that is not a row of
the table, `0`, `null`, or anything that is not an integer is an error; use a
pointer field for an optional value. The file compiles only once go-enum has
generated its companion: `UnmarshalJSON` uses `IsValid` and `ErrInvalid…`.

Then run `go generate` on that directory: go-enum writes the constants
(`evenementtype.RdvDEstimationID`, …), `String`, `ParseEvenementType`,
`IsValid` and `EvenementTypeValues`.

A file is rewritten in full on every run. The package of an entry removed from
the config file is not deleted.

### Names

A `_` is inserted at each camelCase boundary (`agendaGoogle`, `DDVProposition`),
then the label is lowercased, `œ`/`æ` become `oe`/`ae`, accents are stripped,
every run of characters outside `[a-z0-9]` becomes one `_`, leading and
trailing `_` are removed, and `_ID` is appended. The uppercase suffix makes
go-enum write the constant the Go way: `AgendaGoogleID`, not `AgendaGoogleId`.

| label | name | constant |
|---|---|---|
| `RDV d'estimation` | `rdv_d_estimation_ID` | `RdvDEstimationID` |
| `Événement d’entreprise` | `evenement_d_entreprise_ID` | `EvenementDEntrepriseID` |
| `Cœur de cible` | `coeur_de_cible_ID` | `CoeurDeCibleID` |
| `agendaGoogle` | `agenda_google_ID` | `AgendaGoogleID` |

### Errors

Nothing is renamed, numbered or skipped. Generation stops, and no file is
written for any table, when:

- `output` is missing, there is no `[[enum]]` entry, or two entries give the
  same package name;
- the table or one of the two columns does not exist, or the id column is not
  an integer;
- the table has no rows;
- an id is NULL, appears twice, or is not above 0 (`0` is the zero value of
  the type, so it is never a valid row);
- a label is NULL, has no usable character, or starts with a digit;
- two rows give the same name;
- a comment has a `)` without its `(`: go-enum would end the enum there and
  drop the rows after it.

### Tests

Unit tests need nothing. The integration tests read a real database:
`go test -tags integration ./internal/pkg/enum/` (Docker, or `MMW_DUMP_TEST_DSN`
pointing at a server where the role can create databases).
